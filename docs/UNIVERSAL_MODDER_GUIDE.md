# Руководство по плагину `universal-modder` для DWDN

> Подробное руководство о том, **зачем, когда и как** использовать локально установленный плагин [**`universal-modder`**](https://github.com/rehan-remade/universal-modder) (скиллы, специализированные субагенты, CLI `um` и базу знаний по Bannerlord) при разработке модуля **Daewden (DWDN)**.

---

## 1. Зачем использовать `universal-modder` в DWDN

Разработка сетевого модуля *Mount & Blade II: Bannerlord* регулярно упирается в сложные задачи на стыке управляемого кода (`.NET 4.7.2` клиент / `.NET 8` сервер), нативного ядра (`TaleWorlds.Native.dll`), бинарных ассетов (`.tpac`) и живого тестирования в игре.

Плагин `universal-modder` решает эти проблемы системно:
- **Готовые протоколы без «изобретения велосипеда»:** проверенные пошаговые инструкции по разведке движка, реверс-инжинирингу, пайплайну ассетов, автоматизации запуска игры и предрелизной проверке.
- **Специализированная база знаний по Bannerlord:** содержит `engines/bannerlord.md`, а также технические заметки по нативным крашам/зависаниям (`bannerlord-native-crashes-and-hangs.md`) и сборке ассетов без Modding Kit (`editor-free-bannerlord-assets.md`).
- **Безопасное разделение ролей субагентов:** отделяет офлайн-исследование и генерацию кода (`mod-offline-worker`) от манипуляций с живым процессом игры (`mod-game-worker`), исключая гонки и порчу окружения.
- **Автоматизация рутины (`um` CLI):** поиск по базе знаний, резервное копирование конфигов/сейвов, обработка спрайтов и 3D-рендеров, запись геймплейных роликов и предрелизный линт.

## 2. Карта скиллов: когда и зачем вызывать

Каждый скилл лежит в `skills/<name>/SKILL.md` установленного плагина и активируется перед началом соответствующей задачи.

### Основные скиллы для DWDN (использовать регулярно)

| Скилл | Когда вызывать | Зачем и что даёт в DWDN |
|---|---|---|
| **`mod-any-game`** | Старт любой новой игровой фичи (класс, оружие, артиллерия, UI, механика) | Задаёт безопасный цикл: разведка → выбор маршрута → вертикальный срез → верификация в игре. Содержит `references/engines/bannerlord.md` и `references/safety.md`. |
| **`reverse-engineering`** | Краш/зависание в `TaleWorlds.Native.dll`, поиск скрытых полей, разбор `.tpac`/`.rdc` | Методика декомпиляции .NET (`ILSpy`), анализа нативного кода (`Ghidra`/IDA), разбора бинарных форматов с проверкой round-trip и анализа памяти/рендера (`RenderDoc`). |
| **`game-recon`** | Выход нового патча Bannerlord, смена версии сервера, проверка окружения | Сбор точных фактов об установленной игре: `Version.xml`, пути модулей, управляемые/нативные DLL, логи, конфиги. |
| **`game-automation`** | Нужно запустить игру/сервер, прокликать меню, снять скриншот или прогнать тестовую сцену | Безопасный запуск в оконном режиме, GPU-безопасные скриншоты, очистка crash-репортеров, корректное завершение по PID, чтение логов. |
| **`asset-pipeline`** | Подготовка новых иконок, UI-спрайтов, текстур, рендера 3D-моделей | Обрезка, приведение к размерам, спрайт-листы, бесшовные текстуры, маски командных цветов, рендер через Blender. |
| **`publish-mod`** | Подготовка нового релиза DWDN перед слиянием `development` → `main` | Предрелизный аудит (проверка, что не утекли файлы игры, декомпил, ключи или личные конфиги), оформление README, версионирование и чеклист релиза. |
| **`share-field-notes`** | В начале сложного исследования и в конце сессии после найденного решения | Поиск уже решённых проблем движка до старта и фиксация новых находок (в паре с [`docs/CHRONICLE.md`](CHRONICLE.md)). |

### Дополнительные скиллы (по ситуации)

| Скилл | Когда применять |
|---|---|
| **`game-research-websearch`** | Поиск старых тем моддинга Bannerlord, восстановление мёртвых ссылок через Wayback Machine/archive.today, поиск по GitHub/Nexus/Steam Workshop. |
| **`fal-assets`** | Генерация концептов, иконок с прозрачным фоном, PBR-текстур, 3D-моделей, SFX и музыки через `fal.ai` / `um fal`. |
| **`showcase-video`** | Запись окна игры (только со звуком игры) и автоматический монтаж короткого демо-ролика или трейлера патча DWDN. |
| **`port-a-mod`** | Перенос стороннего или старого мода Bannerlord на актуальную версию движка (`v1.5.7+` / `.NET 8` сервер) без потери поведения. |
| **`mashup-mods`** | Экспериментальные кросс-игровые механики и тотальные конверсии. |

## 3. Субагенты `universal-modder`: как распределять работу

Для крупных многоэтапных задач по моду плагин предоставляет три специализированных субагента с жёстким разделением ответственности:

```text
                  ┌──────────────────────┐
                  │   mod-orchestrator   │  Планирует этапы, сверяет факты,
                  │    (супервизор)      │  отвечает на вопросы, отчитывается
                  └──────────┬───────────┘
              ┌──────────────┴──────────────┐
              ▼                             ▼
┌──────────────────────────┐  ┌──────────────────────────┐
│    mod-offline-worker    │  │     mod-game-worker      │
│  НИКОГДА не запускает    │  │  ЕДИНСТВЕННЫЙ, кто       │
│  игру. Изучает DLL/XML,  │  │  собирает, деплоит и     │
│  декомпил, пишет патчи,  │  │  запускает реальную игру │
│  генераторы и юнит-тесты │  │  или сервер для замеров  │
└──────────────────────────┘  └──────────────────────────┘
```

### Зачем соблюдать это разделение
1. **Нет конфликта за файлы и процессы:** пока `mod-game-worker` тестирует сборку на живом клиенте/сервере, `mod-offline-worker` параллельно анализирует дампы, XML или пишет генераторы — они не блокируют `DWDN_Script.dll` друг другу.
2. **Честная верификация:** офлайн-агент проверяет статику и `Tools/MechanicsTester`, а игровой агент подтверждает реальное поведение в бою/лобби и снимает фактические логи и скриншоты.

### Когда запускать субагентов, а когда работать напрямую
- **Мелкая точечная правка** (баланс в XML, фикс одного метода, документация) → работайте напрямую, без оркестратора.
- **Крупная фича или сложный краш** (например, отладка зависания артиллерии на сервере + правка физики + проверка в реальном матче) → используйте `mod-offline-worker` для исследования и патча и `mod-game-worker` для деплоя и проверки в игре (или `mod-orchestrator` для полной координации).

## 4. База знаний Bannerlord и CLI `um`

Внутри плагина встроен CLI `um` и локальная база знаний (`knowledge/`). Перед тем как тратить время на повторный реверс-инжиниринг движка, проверьте готовые материалы:

```powershell
# Поиск всех заметок и техник по Bannerlord в локальной базе знаний плагина
um kb search "Bannerlord"

# Быстрая разведка установленной версии игры (читает Version.xml и бинарники)
um scan

# Резервное копирование сохранений и конфигов перед экспериментальным запуском
um backup
```

### Ключевые справочные файлы плагина для Bannerlord
- `skills/mod-any-game/references/engines/bannerlord.md` — маршруты моддинга (Data/XML, C# `MBSubModuleBase`, Harmony, Native, `.tpac`), правила порядка загрузки и валидации.
- `knowledge/techniques/bannerlord-native-crashes-and-hangs.md` — диагностика нативных крашей и зависаний в `TaleWorlds.Native.dll` через минидампы и защиту со стороны управляемого C#.
- `knowledge/techniques/editor-free-bannerlord-assets.md` — работа с ассетами `.tpac`, скелетами и анимациями без запуска официального Modding Kit.

## 5. Типовые сценарии (Playbooks) для DWDN

### Сценарий A: Краш `0xC0000005` или зависание сервера
1. Прочитать [`docs/AI_MODDING_GUIDE.md`](AI_MODDING_GUIDE.md) (раздел защиты от крашей) и выполнить `um kb search "Bannerlord"`.
2. Активировать скилл **`reverse-engineering`**: сверить сигнатуры и поведение в реальных DLL текущей установленной версии Bannerlord (через `ILSpy` / минидамп + `Ghidra` на копии `TaleWorlds.Native.dll`).
3. Добавить защитную проверку в управляемом C# (в DWDN нативный патч обычно не нужен — краши в `Native.dll` почти всегда вызваны невалидными данными/вызовами из C#).
4. Собрать обе DLL (`Client` + `Server`), прогнать `Tools/MechanicsTester --cli`, затем проверить в игре (напрямую или через `mod-game-worker`).
5. Зафиксировать первопричину и фикс в [`docs/CHRONICLE.md`](CHRONICLE.md).

### Сценарий B: Добавление новой игровой механики или класса
1. Сверить локальную установку и зависимости (**`game-recon`** / `Version.xml`).
2. Активировать **`mod-any-game`**: сначала сделать минимальный рабочий вертикальный срез, не ломая существующие классы и сетевые сообщения.
3. При необходимости новых иконок или текстур прогнать их через **`fal-assets`** → **`asset-pipeline`**.
4. Проверить XML и синхронизацию (`Tools/ModValidator` + `Tools/MechanicsTester --cli`).
5. Запустить живую проверку в игре (**`game-automation`** / `mod-game-worker`).

### Сценарий C: Подготовка и выпуск релиза
1. Пройти предрелизный чеклист из **`publish-mod`** (убедиться, что в коммите нет декомпилированного кода, временных файлов, локальных паролей и файлов базовой игры).
2. При необходимости снять демо-клип через **`showcase-video`**.
3. Провести изменения через `feature/*` → PR → `development` → PR (`@Havi-Dorgeir`) → `main` (авторелиз по [`docs/GITHUB_WORKFLOW.md`](GITHUB_WORKFLOW.md)).

## 6. Обязательные правила безопасности при работе с плагином

1. **Истина — текущая установка игры:** заметки в `universal-modder` могут ссылаться на старые версии Bannerlord (например, `v1.4.8`), тогда как DWDN работает под актуальным клиентом и `.NET 8` сервером (`v1.5.7+`). Всегда проверяйте реальные `TaleWorlds.*.dll` текущей установки.
2. **Никакого декомпила и дампов в репозитории:** выводы `ILSpy`, базы `Ghidra`, индексы и минидампы держите **строго за пределами** репозитория `DWDN_Module` (например, во временной рабочей папке).
3. **Не смешивать с игровым кодом без причины:** используйте скиллы как методологию и инструменты, соблюдая главное правило DWDN — минимально необходимые изменения без поломки работающих систем.
